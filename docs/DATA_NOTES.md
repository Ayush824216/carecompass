# Data notes

Structure and label distributions only. No raw rows are reproduced here. Raw files live in `data/` (gitignored).

## 1. Dev data (`dev_data/`, synthetic, self-generated, committed)
Generated by `scripts/make_dev_data.py` (seed 42, templates + randomisation, no LLM).
- `vignettes.csv`: 400 rows, columns `id,text,language,care_type,urgency`.
  - care_type: gp_teleconsult 129, paramedic_home_visit 76, specialist_referral 76, emergency_referral 63, nurse_home_visit 56
  - urgency: routine 187, same_day 150, immediate 63 (immediate is 15.8%, all emergency_referral)
  - language: hinglish 188, en 132, hi 80
  - Includes negations ("saans ki dikkat nahi hai", "no chest pain"), Hinglish spelling variants, family members, durations.
- `caregivers.json`: 60 mock caregivers (15 paramedic, 15 nurse, 15 gp, 15 specialist) in Delhi NCR, with fields
  `caregiver_id, name, role, skills, lat, lng, availability_slots (ISO, IST, 3 days), languages, rating`.
  Stale dev slots are shifted to start today at load time (`data_adapter._shift_stale_dev_slots`).
- `taxonomy.json`: 5 care types and 3 urgency levels with English/Hindi definitions, plus 15 red-flag categories.

## 2. Public datasets (`data/public/`, gitignored)

### KTAS: `ktas/data.csv`
- Semicolon-separated, **latin-1** encoding (utf-8 fails). 1,267 rows × 24 columns.
- Columns: Group, Sex, Age, Patients number per hour, Arrival mode, Injury, Chief_complain, Mental, Pain, NRS_pain,
  SBP, DBP, HR, RR, BT, Saturation, KTAS_RN, Diagnosis in ED, Disposition, KTAS_expert, Error_group,
  Length of stay_min, KTAS duration_min, mistriage. The vitals columns are strings (comma decimals, blanks).
- `KTAS_expert`: 1: 26, 2: 220, 3: 487, 4: 459, 5: 75. Mapped 1–2 → immediate (246), 3 → same_day (487), 4–5 → routine (534).
- Chief complaint: free English text, 417 unique values, heavily abbreviated ("abd pain", "dyspnea", "ant. chest pain").
- Age 16–96 (median 57). Mental: 1 alert 1187, 2 verbal 39, 3 pain 28, 4 unresponsive 13.
- **Used**: Chief_complain, Age, Mental, Injury (triage-time only). **Never used**: Diagnosis in ED, Disposition,
  Length of stay, KTAS_RN, Error_group, mistriage (outcome or leakage columns).

### Disease-symptom (itachi9604): `symptom_severity/`
- `dataset.csv`: 4,920 rows, `Disease` + `Symptom_1..17`; 41 diseases (120 rows each, many duplicates).
- `Symptom-severity.csv`: 133 rows, `Symptom,weight` (weights 1–7: 1:1, 2:15, 3:21, 4:39, 5:35, 6:17, 7:5).
  Used to build `data/processed/severity_lexicon.json`.
- `symptom_Description.csv`, `symptom_precaution.csv`: 41 rows each. **Not used**; precautions are never surfaced.

### Symptoms to diseases (abhishekgodara): `symptoms_to_diseases/`
- `final_symptoms_to_disease.csv`: 192,715 rows, `diseases,symptom_text` (comma-joined symptoms, mean 5.6 per row);
  254 diseases, 402–1,219 rows each. This file is used, and only a sample of it.
- `data.csv`: 246,945 rows × 378 one-hot symptom columns (~190 MB). Not loaded (same information in wide form).

## 3. Processing (`scripts/prepare_public_data.py` → `data/processed/public_train.jsonl`)
- KTAS → 1,267 rows `{text: "<complaint>, <age group>, [mental state], [after an injury]", urgency, care_type: null}`.
- Diseases → `config/disease_to_care_type.json` (INTERNAL ONLY, all 254 + 41 diseases mapped), then a sample of
  20 rows per disease turned into English symptom sentences: 5,384 rows
  (specialist 3,040, gp 1,294, emergency 650, paramedic 340, nurse 60).
  The disease names never leave the processing step.

## 4. Official organiser data (`data/official/`)
Not released yet. `backend/app/data_adapter.py` picks up `*train*`/`*vignette*`, `*caregiver*` and `*taxonomy*`
files from OFFICIAL_DIR automatically. Column and label names are mapped through `config/label_map.json`.
